# Development stage report

Each stage below preserves an executable application. Mathematical detail and units are in `formulations.md`. Tests are executable with `python -m pytest`; this report distinguishes implemented reduced-order functionality from incomplete research scope.

| Stage | Functionality and relevant formulation | Files | Verification and outcome | Remaining scope |
|---|---|---|---|---|
| 1. Data/geography | Observed polygons, projected areas, exact canonical BBL join, historical Zone J DA/RT and aligned reanalysis; UTC-aware settlement integrals | `data/download.py`, `inputs.py`, `quality.py`, `weather_import.py` | 1,000 unique BINs; 883 matched tax lots; strict missing-data and native-price-integral tests pass; district browser view inspected | LL84 calibration, direct NSRDB, historically versioned geometry; EPW import not empirically exercised |
| 2. Physical DERs | PVWatts/Faiman; battery first-law balance; exact-discrete RC model; EV cumulative service | `models/physics.py` | PV, battery, thermal, EV, wind/tank standalone tests pass | Survey calibration; wind/tank dispatch integration; EnergyPlus comparison |
| 3. Electrical network | Synthetic multi-voltage network; Newton–Raphson AC; snapshot nonlinear AC OPF | `models/network.py` | Conservation, overload detection, IEEE 33-bus voltage/losses, independent OPF checks and file import tests pass | Unbalance, fault/protection models and verified utility topology |
| 4. Multi-period optimisation | Sparse branch LinDistFlow, conservative P/Q polygons, intertemporal states, terminal SOC, explicit negative-price modes | `optimisation/dispatch.py` | Feasibility/objective/negative-price tests pass; 96-step community trajectory AC-checked; 1,000-building short-horizon case executed | Exact multiperiod nonlinear or conic OPF; AC corrective dispatch |
| 5. Controllers | First-action receding horizon; causal forecasts; local/rule/central/network control; P/Q sharing ADMM | `controllers/forecast.py`, `distributed.py`, `core/simulation.py` | State-update and historical-information tests pass; ADMM stopping residuals and central reference agreement checked | Large-horizon ADMM benchmarks, mixed-integer decomposition, learned forecasting |
| 6. Flexibility | Baseline-minus-control sign convention; signed constraints; sustained MILP envelopes; AC verification and hypothetical conditional settlement | `flexibility/analysis.py` | Signed event calculations and duration/AC-checked envelope tests pass | Complete notification/activation/resource eligibility model and annual service experiments |
| 7. Economics | Import/export/wear/demand accounting; no-DER/control references; discounted cash flows; seeded NPV scenarios; enumerated sizing | `economics/finance.py`, `experiments/sizing.py` | Independent NPV/payback, separate settlement and reproducibility tests pass | Real tariff reconstruction, annual calibrated inputs, tax/fuel/eligibility, continuous co-investment |
| 8. Interface | Nine data-driven workspaces; detailed windowed urban scene with observed roads/water, estimated architecture, stored Python traffic, district/street/plan views, selection and numerical playback | `app/command_view.py`, `app/city_api.py`, `app/static/city/`, `visualisation/urban_scene.py`, existing app modules | Page/HTTP tests plus source-geometry, traffic and saved-state coupling checks; browser camera, material, animation and control QA | Photogrammetric façade survey; full publication-figure suite, PDF, external-resource views |
| 9. Reproducibility/publication | SQLite registry, immutable numerical artifacts, provenance/input/model hashes, CLI experiments, constrained installation, CI | `core/storage.py`, `experiments/`, `pyproject.toml`, `.github/workflows/`, documentation | Persistence/export tests pass; measured 16/64/500/1,000-building short experiments | GitHub remote publication requires a repository-creation/push route; no published-remote claim |

Standalone model equations are implemented where noted, but are not represented as dispatch-integrated features. No unsupported capability is represented by an inactive control or predetermined numerical output.
